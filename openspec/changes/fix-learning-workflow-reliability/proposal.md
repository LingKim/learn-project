# Proposal：修复既有学习闭环可靠性

## 范围与授权

2026-10-03 用户要求检查项目、拆分可并行任务并在独立 Git worktree 实际推进，随后确认“好的 那你把任务分下去”。本轮是已批准练习/学习资产规格的 bug 修复，不新增产品行为、页面设计、权限范围或公开 API。主工作区仅 `.gitignore` 有用户未提交修改，保持原样。允许必要本地提交；禁止 push、PR、部署与覆盖主工作区。

## 已复现问题

1. 练习 `fail_run()` 忽略执行器给出的 `retryable=False`，可将终止性错误误标为可重试。
2. 复习结论按“历史任意相同 digest”去重，来源失效后恢复到相同版本时无法追加恢复结论。
3. 前端提交等候保存期间继续输入，会使用陈旧答案版本提交。
4. 同一练习组件收到新的 set/run 路由参数后仍查询旧任务。
5. 来源读取返回 404 后仍保留旧原文 Query 缓存。
6. 精讲页面沿用旧任务状态；旧练习页面卸载后的迟到请求仍可能导航回旧位置或提交旧操作。
7. 全局 QueryClient 在账号间共享，换账号可能继续显示旧私有结果；集成者按认证状态与用户 ID 隔离 QueryClient/页面生命周期。

每个问题均由对应 agent 在修复前新增回归展示失败，修复后验证。实际最终结果见 evidence。

## 非目标

不新增质量工单、Prompt 管理、计时测评、任务中心或面试；不改变题型/门槛/掌握状态规则，不修改数据库 schema，不重启当前运行进程，不评测真实模型或用户资料。

## 验收

- 保存已确认的最新答案版本后才能提交；切换路由按当前对象恢复任务。
- 不可重试失败和业务禁令均得到尊重。
- 来源可用→失效→恢复的结论追加且重放幂等，旧历史记录兼容。
- 来源失效不继续持有对应原文缓存。
- 三个分支在独立集成分支整合，完整静态检查、测试、契约检查和用户要求的构建准确报告；不冒称浏览器/人工/生产验收。
