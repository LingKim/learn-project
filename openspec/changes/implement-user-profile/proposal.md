# Proposal：实现个人资料与默认画像

## 背景

当前 `User` 只保存用户名、昵称、密码哈希、角色、状态和最后登录时间等账户字段，项目尚无个人画像表、头像字段、个人资料 API 或对应页面。出题、模拟面试和学习计划如果只能在每次任务中重复询问岗位、年限和技能，会降低使用效率；如果把一次任务中的临时输入直接写回用户表，又会造成错误画像和隐私边界混乱。

PRD v0.10 已确认新增可选的“个人资料与求职画像”。它提供用户主动维护的默认上下文，但不替代任务显式输入、简历/JD 和有证据的薄弱点，也不向管理员开放。

## 目标

- 建立与 `User` 一对一的 `UserProfile`，保存目标岗位、工作年限月数、岗位等级、技能、关注知识点、学习目标、默认语言和头像引用。
- 提供个人资料读取和乐观锁更新 API；用户名只读，昵称继续由 `User` 管理但在同一资料页面编辑。
- 复用 `StoredObject`、`FileAsset`、上传会话、RustFS 和清理队列实现私有头像，不创建 `KnowledgeBaseFile`。
- 头像完成真实类型、解码、像素和动画校验，清除 EXIF，并生成统一方形 WebP 后才原子切换。
- 在个人资料页展示当前用户有证据的活动 `Weakness`，但不把薄弱点复制到画像 JSON，也不允许用户自由文本冒充系统诊断。
- 为后续 Prompt 上下文解析提供稳定、可授权、可追踪的画像来源；任务临时值不会自动回写画像。

## 依赖

- 复用现有双 JWT 当前用户鉴权、统一 API envelope、RFC 9457、`ApiStatusCode` 和 SQLAlchemy 公共 Mixin。
- 复用文件管理的 `UploadSession`、`StoredObject`、`FileAsset`、对象存储 provider、审计与异步清理能力，并扩展独立 `avatar` purpose。
- 前端继续遵循组件 → query/mutation options → feature `api.ts` → 共享协议层 → generated SDK。
- `Weakness` 领域尚未实现时，资料接口返回空的活动薄弱点集合，不创建占位或无证据数据。
- `implement-prompt-management` 只消费本变更提供的已授权画像快照，不直接修改个人资料。

## 非目标

- 不建设强制首次引导、职业测评、自动推断岗位等级或自动完善画像。
- 不把简历/JD 解析结果、模型推断或单次任务输入自动保存为用户画像。
- 不把系统识别薄弱点保存到 `UserProfile`，也不允许管理员维护用户画像。
- 不新增公开头像、头像图库、社交主页、邮箱、手机号、真实姓名或第三方账号绑定。
- 不把头像放入知识库，不执行 OCR、Embedding、RAG 或内容理解。
- 本变更不实现题目、面试或学习计划业务，只提供它们后续可消费的默认画像。

## 成功标准

- 当前用户可以读取并更新自己的可选画像；跨用户、管理员账户管理接口和未认证请求无法读取或修改画像。
- 工作年限以月数唯一存储，API 生成一致展示文案；岗位等级、标签数量、长度和默认语言受到稳定校验。
- 携带陈旧资料版本的更新返回 409，不覆盖其他设备的新值。
- 合法头像上传后只在服务端处理成功时切换，失败继续使用旧头像；删除后恢复昵称首字默认头像。
- 头像对象保持私有，数据库不保存签名 URL；旧头像和删除头像通过幂等任务清理且不误删当前头像。
- 个人资料页不设置强制完成门槛，修改密码和删除账号保持独立流程。
- 自动化覆盖字段校验、乐观锁、所有权、头像安全、失败保留、原子切换、清理和管理员不可见性。

## 风险

- 头像解码可能造成内存或 CPU 资源耗尽；必须在完整解码前后实施字节、尺寸、像素、帧数和超时限制。
- 头像切换与旧对象清理若不解耦，失败可能造成用户无头像或误删新头像；必须先生成新资产、事务切换引用，再按引用复核异步清理旧资产。
- 把薄弱点作为静态画像会丢失来源与时效；本变更只读取 `Weakness` 的活动投影。
- 多设备更新可能覆盖字段；首期采用资料级乐观锁，不做复杂字段级自动合并。
