# Proposal：实现文档解析、索引与可验证检索

## 背景

认证、知识库与文件管理后端、内容库前端以及 RustFS 上传、下载、移动、删除和异步清理已经交付。文件完成服务端校验后准确进入“已上传·待解析”，但当前没有正文提取、结构化分块、Embedding、向量索引或检索能力，导致 M1 内容库仍不能作为后续问答、出题和知识精讲的资料底座。

现有 `FileCleanupTask` 面向上传校验与清理，虽然已有持久化领取、幂等键、租约和 `FOR UPDATE SKIP LOCKED`，但没有长任务续租、阶段进度、解析版本、结果引用或可重试性分类，并在单个数据库事务内执行外部存储操作，不适合直接承载文档解析。

## 目标

- 自动解析 PDF、DOCX、TXT 和 Markdown；对扫描 PDF 与混合 PDF 中缺少有效文字层的页面按需执行页面级 OCR，并保留可定位来源结构和提取来源。
- 对正文进行结构感知分块，使用 Qdrant 保存版本化向量索引。
- 使用 LlamaIndex 承担受控文档节点转换、索引与 Retriever 抽象和混合检索组合；项目领域模型与 PostgreSQL 继续掌管正文、分块元数据、权限、任务、活动版本和 Trace，Qdrant 只掌管可重建向量点与索引。
- 使用 `qwen3.7-text-embedding` 生成 1024 维向量，使用 Cosine 距离。
- 结合 PostgreSQL 全文检索与 Qdrant 向量检索形成混合召回，并用 `qwen3-rerank` 对候选文本二次排序。
- 以 PostgreSQL 授权范围驱动 Qdrant payload filter，并在正文加载时再次校验当前权限和活动版本；通过持久化任务与周期对账处理双库清理，不依赖不存在的跨库事务。
- 建立轻量通用异步任务骨架，提供真实阶段、取消、重试、租约续期和幂等发布。
- 提供受保护的用户级检索 API，返回证据片段、分数和页码/段落来源。
- 为每次检索生成可回放的 `trace_id`，记录解析/索引与检索策略版本、各召回通道、融合、Rerank、最终引用、耗时和错误的脱敏链路元数据。
- 更新内容库页面，展示解析阶段、PDF OCR 页数、图片未识别提示、失败原因、重试和重新解析。
- 建立固定四类文档评测集，分别报告混合召回和 Rerank 后质量，并支持 BM25-only、Vector-only、Hybrid-only、无 Rerank 和完整策略的消融回放。

## 非目标

- 不生成 AI 回答，不实现资料模式会话、历史问答或自动标题。
- 不在本变更实现用户反馈表单或管理员诊断台；其产品与技术边界由独立的 `implement-ai-quality-feedback-console` OpenSpec 定义，本变更只交付其依赖的 Trace 地基。
- 不实现基于资料出题、知识精讲、笔记或难点资产。
- 不执行 DOCX/Markdown 内嵌图片 OCR、通用图片 OCR、图片语义理解、图文向量或视频解析；PDF 页面级 OCR 属于本变更目标。
- 不使用 `qwen3-vl-embedding` 或 `qwen3-vl-rerank`。
- 不建设完整任务中心、站内通知或管理员批量迁移页面。
- 不静默重建全部历史文件，不实现跨用户解析结果共享。
- 不把 LlamaIndex 的内存对象、默认文档存储或默认向量存储作为业务事实源，不允许框架在 SQL 权限范围之外先全局检索再应用层过滤。
- 不运行 Next.js build 或 Docker image build。

## 成功标准

- 四类文档均能形成可定位、可版本化、可删除的解析结果和索引；纯扫描 PDF 与混合 PDF 的 OCR 页面保留 1-based 页码、提取来源和质量信号。
- LlamaIndex 在真实文档处理与检索链路中承担已定义职责，并有自动化测试证明不是仅安装或导入。
- 混合检索固定评测集目标证据 `Recall@5 ≥ 90%`，来源定位完整率 100%。
- 跨用户和跨知识库越权结果为 0。
- 删除、移动、取消、重新解析和版本切换不返回陈旧或未发布结果。
- 真实千问 smoke 使用用户明确指定的外部测试文件和本地 `.env` Key；不输出正文、向量、Key 或完整模型响应。
- 任一检索结果都能通过 `trace_id` 还原关键词、向量、融合和 Rerank 的候选 ID/排名变化及策略版本，且 Trace 不向管理员暴露 Query 或片段正文。
- 固定评测集能够输出各消融策略的 Recall@K、MRR、nDCG、无答案判断、P95 延迟和错误率，而不是只报告最终完整链路结果。

## 风险

- Qdrant 与 PostgreSQL 没有跨库事务；发布、删除或重新解析时若门禁与补偿设计错误，可能产生短暂孤儿点、缺失点或陈旧召回。
- Qdrant 成为新的运行依赖，需要锁定版本、健康检查、鉴权、持久化卷、容量门禁、快照恢复与重建演练。
- 千问模型是外部服务，存在限流、超时、鉴权、费用和主干版本漂移风险。
- PDF/DOCX 复杂版式和图片会造成正文不完整；OCR 还会引入错字、版面顺序错误、资源占用和处理时延，产品必须准确提示 OCR 范围、低质量失败和仍未识别的内嵌图片。
- Rerank 可能掩盖基础召回缺陷，因此必须保留并报告重排前指标。
- Trace 可能演变成用户正文旁路或高基数监控标签；必须将诊断事件与普通日志/Prometheus 分离，并限制字段、保留期和访问权限。
- 用户资料会发送给千问服务处理；正式生产前仍需核对服务协议中的留存、训练使用和地域边界。
