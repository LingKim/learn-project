# Proposal：认证入口前端页面

## 背景

Pen 已完成登录、注册和临时密码首次登录强制改密设计，但当前前端仍只有工程状态页，OpenAPI 也尚未提供认证接口。需要先把三个认证入口按已确认 PRD 落为可访问、可校验、可响应式展示的前端页面，为后续认证契约联调建立稳定 UI 边界。

## 目标

- 新增登录、注册、首次登录强制修改密码三个前端路由。
- 复用 Pen 的象牙白、阳光黄、浅沙色和左右分栏视觉，并适配移动端。
- 提供字段级校验、密码显隐、密码规则反馈、提交状态提示和页面间跳转。
- 以 PRD 修正 Pen 中“手机号或邮箱”“忘记密码”“用户协议”等冲突内容。

## 非目标

- 不新增或修改后端认证接口、用户表、会话、Cookie 或 Token。
- 不伪造登录、注册或改密成功，不创建重复于后端 OpenAPI 的 TypeScript DTO。
- 不实现找回密码、短信/邮箱验证码、用户协议页、首次引导或工作台。
- 不修改 Pen 设计文件。

## 风险与验收证据

- 风险：当前 OpenAPI 没有认证契约，三个表单只能完成前端校验和接口待接入提示，不能宣称端到端认证可用。
- 验收证据：组件测试覆盖关键字段、PRD 排除项和密码校验；Oxlint、TypeScript 与格式检查通过；不运行 Next.js build。
