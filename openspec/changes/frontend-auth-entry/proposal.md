# Proposal：认证入口前端页面

## 背景

Pen 曾包含登录、注册和临时密码首次登录强制改密设计，但最新 PRD 已取消首次强制改密与管理员重置密码。前端认证入口以登录和注册两个页面为当前基线，并在后端 OpenAPI 完成后接入真实认证闭环。

## 目标

- 保留登录、注册两个前端路由，移除首次登录强制修改密码路由和实现。
- 复用 Pen 的象牙白、阳光黄、浅沙色和左右分栏视觉，并适配移动端。
- 提供字段级校验、密码显隐、密码规则反馈、提交状态提示和页面间跳转。
- 以 PRD 修正 Pen 中“手机号或邮箱”“忘记密码”“用户协议”等冲突内容。

## 非目标

- 本变更本身不新增或修改后端认证接口、用户表、会话、Cookie 或 Token；真实接入由 `implement-authentication` 变更维护。
- 不伪造登录、注册或改密成功，不创建重复于后端 OpenAPI 的 TypeScript DTO。
- 不实现首次强制改密、找回密码、管理员重置密码、短信/邮箱验证码、用户协议页、首次引导或工作台。
- 不修改 Pen 设计文件。

## 风险与验收证据

- 风险：当前 OpenAPI 没有认证契约，两个表单只能完成前端校验和接口待接入提示，不能宣称端到端认证可用。
- 验收证据：组件测试覆盖关键字段、PRD 排除项和密码校验；Oxlint、TypeScript 与格式检查通过；不运行 Next.js build。
