# Proposal：实现提示词工程化管理

## 背景

当前 PRD 已要求各 Agent 分别维护 Prompt、输入输出 Schema 和运行记录，并要求管理员具备版本、评测、发布和回滚能力。但项目尚无提示词领域模型、管理 API、运行时装配器或管理页面。若后续业务 Agent 继续将系统指令硬编码在执行器中，将出现修改无版本、公共规则漂移、运行结果无法关联版本、回滚不可审计和用户资料被错误拼入系统指令等风险。

课程 11.0–11.4 提供了数据库存储、Agent/场景拆分、整数版本、公共模板、变量注入、Redis 缓存和运行追踪的教学参考。本变更吸收其工程化方向，但不照搬单表、`is_active`、启动时缓存预热、字符串直接拼接或“过滤特殊字符即可防注入”等示例。

## 目标

- 为代码中已注册且真实可执行的 Agent 场景建立稳定任务 Prompt；公共/Agent 片段也必须被至少一个真实场景声明依赖，不预建空角色和假模板。
- 支持公共规则、Agent 角色和任务场景三层组合，并在发布时固定全部依赖版本。
- 支持草稿、不可变发布版本、退役、停用、并发发布保护和产生新版本的审计式回滚。
- 使用代码注册的 Pydantic 上下文/输出 Schema 校验变量、渲染和结构化输出边界。
- 按字段执行“本次显式输入 > 本次选择的业务资产 > UserProfile 默认画像 > 场景默认值”，明确省略与显式 `null` 的不同语义，并固化来源快照。
- 使用合成固定评测集完成预览、实际模型回归和发布门禁，评测证据绑定完整版本指纹。
- 让每次 AgentRun 固化 Prompt、依赖、模型参数和输入/输出引用，使历史结果可精确取回、重跑可解释。
- 提供管理员专用管理 API 和页面，同时阻止普通用户、运行日志、错误响应和质量工单泄露系统 Prompt。

## 依赖

- 复用现有双 JWT 管理员角色鉴权、`ApiResponse`/`PageResponse`、RFC 9457、`ApiStatusCode` 和公共持久化 Mixin。
- 前端继续遵循组件 → query/mutation options → feature `api.ts` → 共享协议层 → generated SDK。
- 运行时接入依赖至少一个真实 Agent 场景已经具有后端执行器、输入上下文 Schema 和输出 Schema；在此之前不得以合成角色冒充业务接入完成。
- 个性化画像兜底依赖 `implement-user-profile` 提供当前用户可授权的只读 `UserProfile` 快照；系统薄弱点继续读取独立 `Weakness`，不得由 Prompt 管理器写入或伪造。
- 质量诊断台只能提交候选修复建议或评测样例，不能直接调用本变更的发布或回滚动作。

## 非目标

- 不允许普通用户查看、编辑或选择系统 Prompt，也不提供用户自定义 Agent 和工作流编排。
- 不实现可执行 Jinja/Python/脚本模板、任意函数调用、远程 Include 或通过 Prompt 修改工具权限和业务状态机。
- 不把 Redis、Hermes 或新的微服务作为正确性依赖；不因课件示例引入额外框架。
- 不保存渲染后的完整 Prompt、用户资料或模型完整响应到普通日志、审计日志或 Prometheus。
- 不承诺重新调用外部模型能够字节级复现历史题目、报告、笔记或学习计划。
- 不在本变更中实现尚未存在的出题、面试、点评、讲解或笔记业务 Agent。
- 不把单次任务输入、选中资产、模型推断或生成结果自动回写 UserProfile；“保存为默认画像”属于用户明确确认后的独立资料更新流程。

## 成功标准

- 只有注册表中存在的 Agent/场景才能创建、发布和启用任务 Prompt；公共/Agent 片段必须被注册场景声明使用，未知或无人依赖的定义稳定失败。
- 同一定义最多一个活动发布版本；已发布版本及其依赖不可修改，并发发布不会覆盖新版本。
- 公共片段更新不改变既有根版本；AgentRun 能解析到运行时实际使用的全部不可变版本和哈希。
- 未通过变量、依赖、输出 Schema 或固定模型评测的候选版本无法发布。
- 回滚创建新的递增版本并记录历史目标、原因和操作者，历史运行记录和业务结果保持不变。
- 用户资料只进入受控数据消息或工具结果，不被解释为系统模板或可执行指令。
- 每个个性化字段都能解析到 `request | selected_asset | profile | weakness | default` 来源；省略允许兜底，显式 `null` 禁止兜底，必填信息仍不足时不调用模型猜测。
- 管理员可完成列表、编辑、Diff、预览、评测、发布、回滚、停用和审计；普通用户与业务接口读取 Prompt 正文的成功结果为 0。
- 自动化覆盖角色越权、缓存泄露、并发发布、陈旧评测、依赖漂移、未知变量、Prompt Injection 载荷和运行快照绑定。

## 风险

- 公共片段若总是读取“最新版本”，会让历史发布内容漂移；必须通过依赖关系固定具体版本。
- 管理员编辑页必须读取 Prompt 正文，与笼统的“系统提示词不得返回前端”存在表面冲突；本变更将其收敛为管理员专用、禁止缓存、有审计的唯一例外。
- 在线固定评测会产生模型调用成本；只允许合成样例、受控并发和明确执行，不在每次保存草稿时自动调用。
- 仅靠字符过滤无法防止 Prompt Injection；需要消息角色隔离、变量白名单、Schema 校验、工具权限和业务状态机共同约束。
- 若只做对象级优先级，画像可能覆盖本次请求中的单个字段；上下文解析必须逐字段合并并保留显式 `null`，不能用字典的简单 truthy 合并。
- 外部模型可能升级或存在非确定性；历史正文通过业务版本取回，模型重跑只能作为新版本和尽力复现。
