# Design：难点资产与文字知识精讲

状态：2026-10-03用户在方案展示后回复“开始开发”，本期方案已批准。接口见api-contract.md，验收义务见specs/learning-assets/spec.md。实现阶段继续冻结Pydantic字段及长度预算，不扩展批准范围。

## 1. 领域边界与来源

新增实际使用的 `backend/src/xuemian_ai/learning_assets/`，包含难点、证据、状态历史、精讲/卡片版本、持久任务与 worker。练习模块仍负责题集、答案、评分和报告，profiles 只聚合当前用户活动难点，不持有证据副本。知识卡片是已保存业务结果；系统 Prompt 保持代码中不可变清单方式，不冒充管理台已交付。

本期来源为 PracticeSubmission＋指定 PracticeGrade 版本，以及用户手动创建。自动识别只在持久事件被处理后运行，不在 GET 报告/列表时写数据，不启动旧资料批量扫描。客观评分、主观worker发布、重评、练习完成与来源练习软删除均在自身事务写事件；不只靠评分事件触发完成后的复习结论。

## 2. 数据与一致性

| 对象 | 责任与关键约束 |
| --- | --- |
| Weakness | owner、title/concept_key、领域/标签、严重度、候选决定、掌握状态、version、来源范围、证据充分性；软删除与用户撤销保留历史 |
| WeaknessEvidence | practice证据关联attempt/revision/question/submission/grade，manual证据记录用户主动创建概念/来源/确认快照且不伪造grade；保存策略/引用版本，不复制整份文件；唯一来源grade＋concept，旧评分证据可被新版替代 |
| WeaknessEvent | 追加确认/忽略/状态改变/撤销/证据修正等事件，不覆盖旧行为，不记录系统 Prompt |
| LearningEvidenceEvent | 与评分/完成/删除同事务落库的 durable outbox；event_type＋对象id/版本唯一，评分事件引用grade_id，完成/删除事件引用attempt/set版本；幂等消费、可重启恢复 |
| KnowledgeExplanation | 本人直接精讲或正式难点精讲的配置、来源快照与活动卡片指针；version/软删除，配置变化不修改已发布卡片 |
| KnowledgeCardVersion | 不可变五部分内容、引用、基础/深度/语言、来源和生成清单、父版本；失败不移动活动指针 |
| KnowledgeRun | owner、operation、目标对象/期望version、输入摘要、request_key、lease token、状态/阶段/错误/result_ref；不强制绑定虚假题集或文件 |
| LearningReview | 关联目标Weakness快照或Explanation/卡片版本与新PracticeSet/Attempt，保存实际提交覆盖、有效评分与验证结论；追加结果版本；难点详情仅聚合本人关联的难点复习 |

复用持久化 Mixin；外键和 owner 联合约束配合服务检查，数据库保证幂等和唯一活动键。确认/编辑/撤销/状态更新使用 expected_version；模型调用在短事务外完成，发布事务再锁定对象、租约及来源快照。首次正式难点入库、卡片任务入队及事件写入同事务完成；重复识别只更新证据，不反复生成卡片。

自动精确去重键为owner＋source_scope_key＋规范化概念名。source_scope_key由模式、知识库及规范化去重排序file_ids或明确“全库”标记构成；不同选中文件范围不能暗中合并，处理版本另存不可变快照、不改变逻辑概念键。名称采用Unicode NFKC、大小写和空白归一化，不用模糊相似或大模型自动合并。不同来源范围不静默合并。用户改名遇到既有活动键返回冲突，保留两者及输入。人工跨概念合并属于后续。

本期Weakness来源范围创建后不可变，名称/标签/严重度可以编辑；同文件处理版本失效后，本人可显式重新生成卡片，按同一范围读取当前版本并固化新快照。需要切换知识库/文件集合/模式时，新建直接精讲或手动难点，不把旧资产的scope键、历史证据和已关联练习改成新范围。精讲配置只有未绑定难点的直接精讲可以明确改变模式/资料范围；绑定难点的卡片配置不得突破该范围。

manual证据表示“用户声明想学习该概念”，可支持该手动活动难点出现在列表/画像选择器；它不是系统诊断或已掌握证据，不参与重复错误和系统验证门槛。资料manual证据还需当前合法范围与可用来源，通用manual证据不要求伪造文件或评分。

## 3. 识别策略（提议 `practice_weakness_v1`）

每道相关题只取最新提交及其最新成功评分；较新提交尚未评分时不把旧提交得分当新结果。一个 question_id 无论题集编辑、重复练习、重评次数如何，只贡献一道独立题；重评不改变回答的时间排序。outbox事件仅触发重新读取当前权威版本，不能用迟到旧事件覆盖较新投影。

当前评分Schema没有维度到topic的归因映射，因此仅单知识点题可参与自动入库与系统验证。多知识点题只产生“本题整体结果与这些知识点相关、具体归因未验证”的待确认候选，不能把总体答错复制成每个子技能已确诊。针对性出题增加服务端门禁：发布用于本次验证的题目必须以选中难点为唯一topic，其他主题题不冒充相关题；不能通过事后改标签伪造模型考查内容。

- 错误/部分正确产生候选。客观结果使用确定规则；主观结果保存维度/实际回答证据，自报 confidence <0.7 标低置信度。
- 自动入库要求30天内至少3道不同中等/困难、单知识点题的有效错误/部分正确，分布在至少2次不同attempt，计入的主观结果均非低置信度；对该概念所有单知识点有效结果按提交时间排序，最近两题也必须错误/部分正确，不能只取错误子集而忽略近期正确结果。展示难度、重复次数、近期结果与门槛版本。满足的是证据策略，不声称统计置信概率。
- 仅一道题、简单题、低置信度或证据不足仍可显示候选，但需用户确认；候选确认保存实际证据及 `user_confirmed` 来源。
- 忽略针对当前候选证据集合；相同事件重放不重新弹回。新独立题可形成新候选，忽略证据不计入之后自动入库的重复次数。
- 已确认资产新增有效证据不重复创建卡片。重评修正使旧证据 superseded；仍可查看旧版本，当前支持不足明确标记，不自动删除用户已确认资产。
- 撤销/软删除后原事件不自动复活资产；新独立证据只形成待确认候选，用户确认前不恢复自动生成。

规则放服务端并保存策略版本，覆盖时间边界、distinct 计数、画像/权限/来源可用性；不从 profile 自由文本识别薄弱点。

## 4. 卡片与直接精讲

知识精讲输入：知识点或单个活动难点、基础（完全不了解/知道概念/用过但不熟/查漏补缺）、深度（快速理解/系统掌握/深入原理）、语言、资料/通用模式。默认“知道概念＋系统掌握”；显式输入 > 所选难点上下文 > UserProfile 允许字段 > 系统默认，省略/null 语义沿用现有规范。

手动创建难点必须明确选择通用或资料范围，不能默默外发无关资料。资料难点自动卡片默认复用原知识库与原选中文件范围，并重新取得当前合法证据，不拿旧评分中的原文充当本次检索。原引用版本改变时阻止自动生成，提示调整来源后显式发起新任务，不静默扩大到整个知识库。

执行链：权限/版本校验 → 固化输入 → 受保护检索（资料模式）→ LangChain 模型结构化生成 → Schema/正文质量/引用校验 → 权限、来源与租约再检查 → 发布不可变卡片。可恢复业务状态由 PostgreSQL 任务掌管，必要的显式编排使用现有 LangGraph 方式；检索复用项目既有 LlamaIndex/检索层，不另建索引。

五部分均需有效内容；示例与误区不得虚构用户事实。资料模式必须有可定位合法引用、证据不足可结构化拒绝；语义是否被资料支持还须合成评测与人工抽样，引用定位不能替代语义验证。通用模式明确说明使用模型知识。理解练习提供自查要点，不建设第二套答题评分，实际验证通过已有刷题流程。

普通生成沿用现有学习模型 Settings；基础/深度/主题按代码 Schema 校验，上限及 token/context budget 实施前在契约中冻结，不截断后声称完整覆盖资料。首次难点确认/自动入库生成一次卡片；读取、播放不存在的音频、重复访问不调用模型。配置调整和重新生成使用新任务及新版本，失败保留旧结果。

## 5. 状态与针对性再练

候选决定 `pending | confirmed | ignored | revoked` 与掌握状态 `to_learn | learning | to_verify | mastered` 独立；候选不混入正式资产默认列表。用户显式调整状态记录事件；生成卡片不等于已经学习，阅读 GET 不自动改状态，不自动宣称掌握。

首版每次针对一个目标：正式难点或某个精讲卡片版本；跳转已有练习创建页，预填可编辑配置，保持原有plan/confirm/generate。PracticeConfig新增可选判别联合`learning_target`：weakness(id/version)或explanation(id/card_version)，固化concept、来源范围与显式上下文。直接精讲再练只记录卡片复习，不隐式创建难点或改画像；难点卡片关联的再练可显式选其Weakness作为目标。不得自动开始练习或用空题集模拟关联；未选择时现有行为保持兼容。

可编辑字段包括题型/题量/难度与画像覆盖，但保留target时主题及来源范围必须兼容其快照。显式改成其他主题、知识库/文件集合或模式时，plan前返回LEARNING_TARGET_MISMATCH并保留输入；用户显式取消目标关联后可以作为普通练习，服务端不覆盖显式输入、不静默删除关联，也不重贴topic伪造兼容。

提议验证规则：completed attempt中相关单知识点题总数至少3道，而且每道均提交、有效评分、全部正确且非低置信度，显示“本次验证通过”，用户决定是否标记已掌握。相关题中的未答/未评分/低置信度均阻止本次验证通过，不能筛掉后只报3道成功题；其他主题不计入相关分母。小于3道为样本不足，不禁止用户手动标记掌握。与难点关联练习的单知识点有效错误/部分正确可令待验证/已掌握回到学习中；多知识点或低置信度只记录待核验结果。

复习统计对每题取最新提交及其最新成功评分；完成事务事件保证评分事件先被消费时仍能产出最终结论，完成后重评追加Review版本，不改写旧记录。系统只能声明题目确有目标concept，其他topics不因为关联了目标而被全部纳入验证。难点在创建后改名/改状态不改变旧题集、回答和卡片；撤销/删除不抹去旧练习，但终止尚未发布的难点生成与自动状态更新。

乱序/重复消费不产生重复Review。自动状态回退还须与目标当前version及最后用户状态事件比较：旧回答/旧练习的迟到消费或重评修正仅更新其复习结论，不因消费时间较晚覆写用户之后的手动状态；仅新的有效错误回答可按批准规则回退状态。

## 6. 私有历史与来源失效

非 owner（含管理员）猜测 ID 返回404，正文 no-store，普通日志仅 ID/版本/阶段/耗时/错误。资料、回答、卡片、Prompt 不进日志/指标/管理员页面。query cache 在来源失效/删除后清除受影响原文，不能靠 disabled button 保留泄露的预览。

文件删除、移动、重解析或活动版本切换时禁止使用旧正文继续生成/评分；已保存本人卡片/题目/回答作为业务结果保留，失效引用不返回片段原文。依赖的练习被软删除后保留事件/来源ID但不能借资产详情绕过删除读回题目/回答；仅剩不可用的证据不参与自动入库、验证和画像活动项。

## 7. 长任务与运行

knowledge-worker 同时消费提交、评分、完成与删除 outbox 与 KnowledgeRun，不扩大 document-worker，不将 PracticeRun 的 set_id 改成无意义占位。默认并发2、租约30秒、任务180秒（已批准）；心跳/lease token/对象version/权限与来源 fencing 防迟到发布，pending 重启可继续，processing 过期失败后明确重试。

模型任务返回202、run ID、真实阶段与 result_ref；请求响应丢失可由 owner＋request_key 找回。自动首次卡片 request_key 从正式入库事件生成稳定键；显式生成用客户端 UUID。重复同输入复用结果，不同输入同key冲突。pending 可立即取消，processing 登记取消并在安全发布点丢弃结果；失败不替换旧卡片，不虚构百分比。

只更新本项目运行入口/Settings，迁移仅触及 learning_assets 及必要 practice 关联。执行迁移前核对 `.env` 目标/current 并可恢复备份，后读回版本与接口；不启停外部 PostgreSQL/Redis，不 build，不自动 commit/push。

## 9. 并行职责与验证

方案批准、Pen校准及 FastAPI 契约冻结后按 AGENTS 启用前后端 subagent：后端负责 learning_assets/迁移/测试；前端负责 feature 页面/API options/组件测试。主 agent 负责 practice/profiles 接入、共享路由/模型/运行入口、SDK生成、自审与集成，避免共享文件并行编辑。

必要验证包括识别和状态规则、outbox重放、角色矩阵、迁移恢复、资料失效、旧报告回归、任务/版本竞争、模型结构/语义合成评测、完整本人浏览器流程及Pen核验。沿用原质量工具，不写镜像实现的无效测试，不以 worker 存活代替业务验收。
