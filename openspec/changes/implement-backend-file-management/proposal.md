# Proposal：实现后端文件上传、知识库文件管理与清理闭环

## 背景

项目当前只有 RustFS 容器和健康检查，没有对象存储客户端、上传会话、文件模型、知识库 CRUD、文件删除接口或持久化清理任务。PRD 已确认知识库、简历、JD 和录音均需要复用统一文件能力，但当前真实存在且可形成纵切的业务模块只有知识库。

本变更先交付后端公共文件基础设施和知识库文件管理接口。文件完成存储与校验后只进入“已上传·待解析”，不把尚未实现的文档解析、分块、Embedding 或检索冒充为已完成。

## 目标

- 建立业务范围内的两阶段上传会话、RustFS 预签名直传、单次/multipart 上传和断点续传能力。
- 由服务端校验真实类型、大小、结构并流式计算 SHA-256；MD5 和客户端摘要不作为可信内容身份。
- 以 `UploadSession -> StoredObject -> FileAsset -> KnowledgeBaseFile` 分层表达临时上传、物理字节、用户所有权和知识库关联。
- 实现知识库列表、创建、重命名、删除，以及文件列表、重命名、移动、下载、重复处理、删除影响预览和删除接口。
- 实现版本化文件策略、管理员管理接口、稳定性限额与上传会话策略快照。
- 使用 PostgreSQL 持久化任务、独立 worker/scheduler、补偿清理和周期对账保证数据库与 RustFS 最终一致。
- 实现可执行、可测试的用户文件清理能力，供后续完整删号业务编排调用。
- 在真实 PostgreSQL、Redis、RustFS 和 FastAPI 服务上通过可重复的 curl 验收矩阵，再导出 OpenAPI 并更新生成客户端。

## 范围

- 后端知识库 CRUD、上传会话、文件资产、知识库文件关联、文件策略、文件审计与清理任务模块。
- RustFS S3 兼容客户端、内部/公共 endpoint 分离、预签名上传下载、bucket 初始化和 readiness 检查。
- PDF、DOCX、TXT、MD 的类型、大小与结构校验；PDF 页数、DOCX 内部结构/解压量/字符/段落、TXT/MD 编码与字符限制。
- 单次上传、multipart、续签、取消、会话过期、服务端 SHA-256、同域物理去重和跨用户隔离。
- 知识库内重复拒绝、同一用户跨知识库关联/移动、幂等写操作和并发约束。
- 删除确认 token、立即撤销访问、异步物理清理、重试、最终失败、每日清理与每周一致性对账。
- Alembic 迁移、后端测试、真实 curl 脚本、OpenAPI 导出与 generated SDK 同步。

## 非目标

- 不开发内容库 React 页面，不修改当前首页路由，不新增前端 feature API、Query 或业务组件。
- 不实现 PDF/DOCX 正文解析、分块、Embedding、向量库、RAG 检索或重新解析用例。
- 不创建尚未真实使用的简历、JD、模拟面试、真实面试、讲解音频或导出业务模块；只保留可复用存储与策略边界。
- 不实现完整删除账号 HTTP 接口；本变更只提供用户文件清理用例。
- 不接入 ClamAV、第三方病毒扫描或其他病毒扫描引擎，也不宣称格式与结构校验能够发现所有恶意文件。
- 不由 Compose 启动、停止、重建或删除宿主 PostgreSQL 与 Redis。
- 不执行 Next.js build 或 Docker image build，除非用户另行明确授权。
- 不 commit、不 push，除非用户在后续轮次明确授权。

## 风险

- 预签名 URL 若使用容器内部地址，浏览器无法访问；必须分别配置内部 endpoint 与外部公开 endpoint，并在生产强制 HTTPS。
- PostgreSQL 与 RustFS 不支持跨系统事务；上传提升、数据库提交和物理删除必须通过状态机、幂等任务和补偿机制收敛。
- 相同文件的并发完成可能重复创建物理对象或错误增加引用；数据库唯一约束、摘要锁和事务内复核必须共同兜底。
- 只相信引用计数可能误删共享对象；有效 `FileAsset` 引用是事实源，删除前必须加锁复核并在不一致时停止。
- DOCX 没有稳定页数语义；本变更不引入 Office 渲染器，改用内部结构、解压量、正文字符和段落限制。
- 不接入病毒扫描意味着格式合法的恶意载荷仍可能存在；原件默认附件下载，解析边界受控，产品和接口不得声称完成病毒检测。
- multipart、失败补偿和定时任务若只用进程内后台任务会在重启后丢失；任务状态必须持久化到 PostgreSQL。
- 全量 bucket 对账可能影响 RustFS；对账必须分页、限批，并对孤儿对象设置至少 7 天和连续两次确认保护期。

## 验收证据

- PRD v0.6 与本变更 Proposal、Design、三份增量 Specification 和 Tasks 一致，无“病毒扫描已实现”“上传即已解析”或“本轮包含前端页面”的冲突表述。
- Alembic 在隔离测试数据库完成迁移验证，表、部分唯一索引、状态约束和幂等约束符合设计。
- Ruff、mypy、pytest 通过，覆盖校验、权限、幂等、并发去重、最后引用删除、任务重试和用户文件清理。
- 真实 FastAPI、PostgreSQL、Redis、RustFS 通过 curl 矩阵；证据只记录状态码、稳定错误码和脱敏断言。
- RustFS 故障注入能够产生可追踪补偿任务，重试上限与最终失败行为符合规格。
- curl 门禁通过后导出 OpenAPI、重新生成前端 Client，并通过 OpenAPI 一致性与前端 API 边界检查；不实现前端业务调用。
- 明确记录未运行的验证项；不得以文件存在、Mock 成功或配置已写冒充真实服务验证。
