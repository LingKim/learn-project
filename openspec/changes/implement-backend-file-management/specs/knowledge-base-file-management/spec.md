# Knowledge Base File Management Specification

## Requirement：用户必须能管理自己的知识库

系统 SHALL 提供当前用户知识库的分页列表、创建、重命名、删除影响预览和删除接口。每个用户 SHALL 始终至少保留一个有效知识库。

### Scenario：创建知识库

- **WHEN** 已认证用户提交合法且不冲突的知识库名称
- **THEN** 系统创建属于该用户的非默认知识库
- **AND** 其他用户不能查询或修改它

### Scenario：删除最后一个知识库

- **WHEN** 用户尝试删除自己的最后一个有效知识库
- **THEN** 系统返回 409 和稳定错误码
- **AND** 不软删除知识库或其中的文件关联

## Requirement：知识库文件列表必须准确表达处理状态

系统 SHALL 分页返回当前用户指定知识库中的有效文件关联，支持展示名称搜索和状态筛选，并分别表达上传、验证和业务处理状态。

### Scenario：文件完成存储但尚未解析

- **WHEN** 文件完成服务端验证并关联知识库，但本变更没有解析实现
- **THEN** 列表显示“已上传·待解析”
- **AND** 不显示“可用”或暗示可以进行 RAG 检索

### Scenario：查询软删除文件

- **WHEN** 普通文件列表或搜索执行
- **THEN** 已软删除的知识库关联不出现在结果中
- **AND** 不生成新的下载或处理能力

## Requirement：文件名称属于知识库关联

系统 SHALL 保留 FileAsset 原始文件名，并允许每个 KnowledgeBaseFile 拥有独立展示名称。重命名 SHALL 只修改当前关联，不修改对象 key、摘要、真实类型或扩展名。

### Scenario：同一文件在两个知识库使用不同名称

- **WHEN** 用户将同一 FileAsset 关联到两个知识库并分别重命名
- **THEN** 两个关联显示各自名称
- **AND** 两者继续引用同一用户逻辑资产和兼容物理对象

### Scenario：通过重命名修改扩展名

- **WHEN** 用户提交与真实类型不一致的新扩展名
- **THEN** 系统返回 422
- **AND** 保留原展示名称

## Requirement：重复文件必须按业务范围处理

同一知识库的相同有效文件 SHALL 被拒绝；同一用户其他知识库中的相同文件 SHALL 允许选择关联、移动或取消。系统 SHALL NOT 通过重复响应泄露其他用户的文件存在性。

### Scenario：同知识库重复

- **WHEN** 服务端摘要命中当前知识库已有的有效文件关联
- **THEN** 系统返回 409 `FILE_ALREADY_ATTACHED`
- **AND** 不创建重复关联或重复解析资产

### Scenario：跨知识库关联

- **WHEN** 摘要命中当前用户其他知识库中的文件且用户选择 LINK
- **THEN** 系统为目标知识库创建新关联并复用 FileAsset
- **AND** 保留原知识库关联

### Scenario：跨知识库移动

- **WHEN** 用户选择 MOVE 且源、目标知识库都属于该用户
- **THEN** 系统在同一事务软删除源关联并创建目标关联
- **AND** 不重新上传或复制物理对象

## Requirement：下载必须重新鉴权并使用短期地址

系统 SHALL 在每次下载请求时验证用户、知识库、文件关联和资产仍有效，并只返回短期附件下载地址。管理员 SHALL NOT 通过管理权限下载用户文件。

### Scenario：所有者下载有效资料

- **WHEN** 文件所有者请求自己有效知识库文件的下载地址
- **THEN** 系统返回默认 5 分钟有效的附件下载 URL
- **AND** 响应不包含永久 object key 或存储凭据

### Scenario：删除后下载

- **WHEN** 文件关联、资产或用户已经软删除，或对象处于删除/已删除状态
- **THEN** 系统返回 404 或等价不泄露响应
- **AND** 不生成新的预签名 URL

### Scenario：管理员下载用户文件

- **WHEN** 管理员请求普通用户文件的下载地址
- **THEN** 系统拒绝访问
- **AND** 管理员权限不得绕过文件所有权

## Requirement：删除必须使用新鲜影响确认

删除文件或知识库前，系统 SHALL 返回影响快照和 5 分钟有效、一次性、绑定用户/资源/模式/版本的确认 token。资源变化或 token 过期时 SHALL 拒绝删除并要求重新预览。

### Scenario：使用有效 token 删除来源

- **WHEN** 用户使用匹配当前资源版本的 token 选择 SOURCE_ONLY
- **THEN** 系统立即软删除业务关联、撤销下载和新任务引用
- **AND** 创建幂等物理清理任务，保留的衍生资产标记来源已删除

### Scenario：使用陈旧 token

- **WHEN** 影响预览后文件引用或资源版本发生变化
- **THEN** 删除返回 409 `DELETE_PREVIEW_STALE`
- **AND** 不执行部分删除

### Scenario：重复提交删除

- **WHEN** 客户端重试已经成功接受的相同删除请求
- **THEN** 系统幂等返回原删除结果
- **AND** 不重复减少引用或误删共享 StoredObject

## Requirement：删除优先于运行中任务

用户删除文件、知识库或账号时 SHALL 立即阻止相关任务提交新结果。无法立即中止的外部调用可以结束，但其结果 SHALL 被丢弃并进入清理流程。

### Scenario：验证完成与删除并发

- **WHEN** 文件删除已经提交，而验证 worker 随后完成
- **THEN** worker 在提交前发现业务资源已失效并丢弃结果
- **AND** 不重新创建关联、下载能力或处理任务
