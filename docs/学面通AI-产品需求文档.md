## 1. 文档说明

### 1.1 编写目的

本文档把课件中的产品设想整理为可供产品、UI、前端、后端、AI 工程和测试共同使用的需求基线，明确：

- 产品解决什么问题，不解决什么问题；
- 用户、智能体和底层能力各自承担什么职责；
- 学习、模拟面试、真实面试复盘和难点沉淀如何形成闭环；
- 首期应交付哪些功能，以及功能达到什么标准才算完成；
- 哪些内容来自课件，哪些是为实现完整产品而补充的工程化要求。

### 1.2 课件内容与产品需求的区分

课件中的课程目标、课后思考、宣传语和教学指令仅作为背景材料，不作为系统功能要求。例如“效率提升 10+ 倍”“节省 90% 无效时间”属于价值主张，当前不能直接作为验收指标。

本文档中的功能要求分为两类：

- **课件明确要求**：课件直接提出的角色、模块、流程和能力；
- **产品化补充**：为实现可用的全栈系统而必须补齐的账户、状态、权限、异常处理、数据追踪和验收要求。

## 2. 产品概述

### 2.1 产品定位

学面通 AI 是面向学习者与求职者的多模态 AI 学习和面试训练平台。用户可以上传学习资料、简历、岗位描述（JD）或真实面试录音，系统通过多个职责明确的智能体完成资料解析、检索问答、个性化出题、测评诊断、语音模拟面试、难点讲解、笔记生成和复盘沉淀。

产品的核心不是“提供一次答案”，而是持续完成以下闭环：

> 输入个人材料 → 形成个人画像 → 训练与测评 → 识别薄弱点 → 针对性讲解 → 沉淀个人资产 → 调整后续计划

### 2.2 产品价值

| 用户问题 | 产品价值 |
| --- | --- |
| 学习资料分散，找不到重点 | 统一内容管理、自动解析和基于来源的 RAG 检索 |
| 刷题与个人技术栈、目标脱节 | 根据资料、简历、JD 和薄弱点生成个性化题目 |
| 不知道自己哪里不会 | 用结构化评分、能力维度和历史趋势定位短板 |
| 学完即忘，成果难复用 | 用户按需生成可编辑笔记，系统沉淀知识卡片、错题和复习任务 |
| 缺少真实面试练习 | 提供可追问的语音模拟面试和完整转写 |
| 面试后只有结果，没有原因 | 对模拟或真实面试生成评分、证据、建议和参考回答 |

### 2.3 目标用户

- 零基础或缺乏系统指导的自学者；
- 准备求职、转行或晋升面试的学生和职场人；
- 需要在较短时间内掌握岗位技能的职场新人；
- 有考研、考证、考编等结构化学习和复习需求的用户。

首期不限制特定人群、学习领域或岗位方向，学习者与求职者均可使用。系统提供通用业务流程，专业内容主要来自用户资料、简历和 JD，不建设覆盖所有领域的内置权威题库。这里的“覆盖所有”表示不设置准入限制，不代表所有专业领域具有同等质量；结果质量仍取决于输入资料、千问模型能力和评测规则。

### 2.4 产品目标

1. 用户能把分散材料转化为可检索、可训练、可复习的个人知识库。
2. 用户能围绕指定资料或岗位完成一轮个性化训练，并获得可解释的反馈。
3. 用户能完成一场语音模拟面试，获得逐题与整体复盘。
4. 用户能上传真实面试录音，获得转写、问题提取和复盘报告。
5. 所有场景产生的薄弱点能够进入同一个个人难点资产库，并影响后续训练与计划。

### 2.5 非目标

- 不承诺替代真人教师、职业顾问或企业面试官；
- 不承诺面试通过、考试通过或固定倍数的效率提升；
- 首期不建设公开课程交易、社区、直播课堂、招聘撮合或企业 ATS；
- 首期不让用户自由编排任意 Agent 工作流；
- 首期不支持智能体之间无约束互相调用，所有业务流程统一经过总控调度。

## 3. 核心概念与业务规则

### 3.1 多模态

系统需要按场景处理以下输入和输出：

- 输入：文本、PDF/DOCX/TXT/Markdown、简历、JD、中文普通话音频；
- 过程数据：文档文本、分块、向量、语音转写、题目、答案、评分；
- 输出：文本讲解、结构化报告、知识卡片、讲解音频、面试语音。

首期不支持视频上传或视频理解。文件领域模型、存储接口和解析任务类型需保留可扩展设计，后续可新增 `VIDEO` 资产类型和视频解析器，但首期前端不得展示不可用的视频入口。

### 3.2 定制化

个性化结果至少应综合以下上下文：

- 用户目标与目标日期；
- 当前基础、自评水平和偏好；
- 用户选定的资料、简历与 JD；
- 历史答题正确率和各能力维度评分；
- 已识别薄弱点、错题和复习记录；
- 最近训练进度和用户反馈。

不得仅在提示词中加入用户昵称就宣称“个性化”。每次生成题目、计划或建议时，应记录实际使用的上下文范围。

### 3.3 多 Agent 协作原则

1. **单一职责**：一个智能体只负责一类核心任务。
2. **总控调度**：业务任务由流程总控 Agent 编排，业务 Agent 不直接相互调用。
3. **结构化交接**：Agent 之间通过约定的数据结构交接，不依赖不可解析的自由文本。
4. **可追踪**：每次任务保留任务状态、输入引用、执行步骤、模型版本、提示词版本和错误信息。
5. **可恢复**：单个步骤失败时允许重试或从失败节点继续，不重复创建已成功的资产。
6. **用户可见**：长任务向用户展示明确进度，失败时给出可理解的原因和下一步。

首期各 Agent 作为同一个后端应用中的独立业务组件实现，分别维护提示词、输入输出 Schema、执行器和运行记录。流程总控使用显式业务状态机调度，不使用一个大提示词模拟全部角色，也不要求每个 Agent 独立部署为微服务。用户端只展示业务阶段和负责角色，不展示系统提示词、内部推理文本或敏感上下文。

### 3.4 知识使用模式

系统提供两种不可在同一会话中混用的知识模式：

- **资料模式**：固定关联一个知识库，可在知识库内选择一个或多个文件。回答和衍生资产必须提供资料引用；资料证据不足时明确拒答。
- **通用模式**：允许使用千问自身知识，所有回答和衍生资产必须标记“模型通用知识”，不得伪装成用户资料来源。

存在已选资料时默认进入资料模式，否则默认通用模式。切换模式或知识库时创建新会话，已有会话始终保留创建时的知识范围。

### 3.5 语言范围

- 首期界面只提供中文；
- 学习资料支持中文和英文文本；
- 问答和生成任务默认输出中文，用户可选择中文或英文；
- 首期不承诺其他语言的解析和生成质量；
- 真实面试录音只支持中文普通话。

### 3.6 业务模式选择

“业务模式”决定用户要执行哪条产品流程，“知识使用模式”决定 AI 回答可以使用哪些知识来源，二者是不同维度，不得混为一个字段。

学习模块支持三种业务模式：

| 模式 | 是否默认 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| 快速回答 | 是 | 用户问题、可选知识库/资料 | 直接回答、来源引用 |
| 知识精讲 | 否 | 知识点或薄弱点、用户水平、可选资料 | 结构化知识卡片、文字讲解、按需讲解音频 |
| 刷题评测 | 否 | 岗位、技术栈、资料、简历或薄弱点 | 题库、评分报告、薄弱点 |

面试模块支持五种业务模式：

| 模式 | 是否默认 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| 快速回答 | 是 | 面试问题、可选知识库/资料 | 面试问题回答、来源说明 |
| 简历优化 | 否 | 简历、可选 JD | 简历分析、逐条建议、新简历版本 |
| 模拟面试 | 否 | 可选简历/JD，或岗位、主题、能力要求 | 语音面试、转写、点评报告、薄弱点 |
| 面试复盘 | 否 | 中文普通话真实面试录音 | 转写、说话人标记、复盘报告、薄弱点 |
| 知识精讲 | 否 | 面试薄弱点或指定知识点、可选资料 | 结构化知识卡片、文字讲解、按需讲解音频 |

学习模块和面试模块入口必须展示清晰的模式选择器，并默认选中“快速回答”。切换业务模式时，页面同步切换输入项、提示文案、提交动作和结果组件，不得沿用与当前模式无关的表单数据。需要知识来源的模式再选择资料模式或通用模式；简历优化、模拟面试和面试复盘使用各自任务上下文，不强制展示知识使用模式选择器。

## 4. 用户角色与权限

### 4.1 外部角色

首期包含“普通用户”和“系统管理员”两个系统角色。普通用户承担学习者/求职者业务角色，拥有以下能力：

- 注册、登录和维护个人学习/求职画像；
- 上传、查看、重命名和删除自己的资料；
- 发起学习、测评、模拟面试和真实面试复盘任务；
- 查看自己的报告、题目、转写、难点和笔记；
- 编辑、归档或删除自己的笔记与难点资产；
- 管理自己的账户和数据。

普通用户开放注册。注册字段为唯一用户名、密码和可重复昵称，不依赖手机或邮箱验证码。注册后自动启用，并创建一个可重命名的“默认知识库”。

不同用户之间的数据必须严格隔离。

### 4.2 系统管理员

系统管理员用于账户管理和系统配置，首期拥有以下能力：

- 查看用户列表和用户基本信息；
- 启用或禁用普通用户并填写原因；禁用后该用户全部登录会话立即失效；
- 管理模型、提示词模板和启停状态；
- 查看不包含用户业务内容的系统运行状态和错误统计；
- 配置文件类型、大小、音频时长、题目数量和录音保留天数等系统参数。

用户基本信息首期限定为：用户 ID、账号、昵称、角色、账号状态、注册时间、最后登录时间。系统管理员不得查看用户上传的学习资料、简历、JD、录音、转写、答题内容、面试报告、难点、笔记或学习计划，也不得通过任务日志间接读取这些内容。

系统管理员账号不开放注册，通过显式、幂等的部署初始化命令创建和维护。初始化不得提供默认密码、不得覆盖既有账号，也不得把同名普通用户自动提升为管理员。首期管理员只管理普通用户的查看、启用和禁用，不能创建或重置任何用户密码，也不能禁用或删除其他管理员，避免引入超级管理员/普通管理员两级权限。

### 4.3 账号规则

- 首期支持注册、登录和用户主动修改密码；
- 首期不提供首次登录强制改密、找回密码或管理员重置密码；用户忘记密码时无法在首期产品内恢复，后续需另行设计具备身份验证的安全重置流程；
- 首期不建设独立的隐私协议页面或隐私授权中心；
- 密码不得明文存储，任何管理能力也不得读取用户原密码；
- 密码至少 8 位并包含两类字符；连续登录失败触发短时锁定；
- 用户改密、用户禁用或删除账号后，原有登录会话全部失效；
- 普通用户只能访问自己的业务数据；
- 用户可以在再次验证密码后删除整个账号；账号及业务数据进入软删除状态，立即退出登录，原用户名不得被重新注册；
- 首期不提供用户或管理员数据恢复入口。

### 4.4 登录会话

- 注册成功后自动登录；登录态采用 Access Token + Refresh Token 双 JWT；
- Access Token 有效期 15 分钟，只保存在前端内存并通过 `Authorization: Bearer` 发送；
- Refresh Token 有效期为绝对 7 天，只通过 `HttpOnly` Cookie 传输，每次刷新必须轮换；
- 服务端保存可撤销的 Refresh 会话摘要；旧 Refresh Token 被再次使用时视为重放，并撤销对应 Token 家族；
- 普通退出只撤销当前设备会话；允许多设备同时登录，各设备会话相互独立；
- “记住账号”只保存用户名，不延长 Access Token 或 Refresh Token 的有效期；
- 注册、登录、刷新、重放和退出必须记录不含密码、Token、Cookie 或请求正文的认证审计事件。

## 5. 智能体角色

| 智能体 | 核心职责 | 主要输入 | 结构化输出 |
| --- | --- | --- | --- |
| 流程总控 Agent | 理解任务、选择流程、调度步骤、合并结果、处理异常 | 用户指令、任务上下文、流程定义 | 执行计划、节点状态、最终结果引用 |
| 资料解析与简历分析 Agent | 解析学习资料、简历和 JD，提取结构化要点 | 文件、文本、文档解析结果 | 文档摘要、知识点、技能、经历、项目、岗位要求、追问点 |
| 出题与题库 Agent | 基于目标和上下文生成题目、管理题目 | 知识点、简历、JD、薄弱点、难度 | 题干、题型、答案要点、评分规则、来源引用 |
| 模拟面试官 Agent | 语音提问、理解回答、实时追问并控制节奏 | 面试配置、题目、实时转写、对话历史 | 面试事件、追问、逐轮转写、结束原因 |
| 点评诊断与复盘 Agent | 评分、给出证据和建议、识别薄弱点 | 题目、评分规则、回答、转写 | 分项得分、证据、建议、参考回答、薄弱点 |
| 难点讲解 Agent | 针对薄弱点生成可学习的标准化资源 | 薄弱点、用户水平、关联资料 | 知识卡片、示例、练习、讲解音频稿/音频 |
| 笔记生成 Agent | 把训练成果整理为可编辑笔记 | 解析、测评、复盘和难点结果 | 结构化笔记、标签、关联来源 |

RAG 知识库和提示词管理器属于底层支撑模块，不作为自主业务角色。

## 6. 功能架构与优先级

课件给出了 8 大核心模块，同时在学习场景中明确提出“个性化学习计划”。由于后者未出现在 8 大模块总览中，本文将其作为贯穿测评、难点和复习的跨模块能力单独列出。

| 编号 | 模块 | 优先级 | 首期定位 |
| --- | --- | --- | --- |
| M1 | 内容库与 RAG 检索 | P0 | 学习与问答的资料底座 |
| M2 | 出题与测评 | P0 | 学习闭环入口与短板识别 |
| M3 | 简历智能分析 | P0 | 面试画像与出题依据 |
| M4 | 语音模拟面试 | P0 | 核心差异化训练场景 |
| M5 | 难点攻克资产库 | P0 | 跨场景薄弱点沉淀 |
| M6 | 笔记本 | P1 | 成果组织与二次编辑 |
| M7 | 真实面试复盘 | P1 | 上传录音后的诊断与复盘 |
| M8 | 提示词管理器 | P1 | 内部质量与版本管理能力 |
| M9 | 个性化学习计划 | P1 | 动态生成复习和训练任务 |

优先级说明：P0 构成可验证的核心产品闭环；P1 在 P0 稳定后补齐完整体验。

## 7. 详细功能需求

### 7.1 M1 内容库与 RAG 检索

#### 7.1.1 内容上传与管理

- 用户以知识库组织资料；注册后自动拥有默认知识库，也可以创建、重命名其他知识库；
- 用户始终至少保留一个有效知识库；创建其他知识库后可以删除默认知识库；
- 用户可上传 PDF、DOCX、TXT 和 Markdown，首期不支持图片 OCR 与视频；
- 上传前展示文件类型和大小限制；
- 文件类型、单文件大小，以及适用场景的 PDF 页数、文本字符数、DOCX 解压量/字符/段落和音频时长限制由管理员配置，前后端必须执行一致校验；该限制属于稳定性保护，不属于商业额度；
- 文件状态至少包含：上传中、解析中、可用、解析失败、已删除；
- 用户可查看文件名、类型、大小、创建时间、解析状态和失败原因；
- 用户可重命名、删除、重新解析和跨知识库移动自己的文件；移动时复用解析结果并立即更新检索归属；
- 删除文件或知识库前展示受影响的会话、题目、报告、笔记和难点数量；用户选择仅删除来源或级联删除衍生资产，默认仅删除来源；
- 仅删除来源时立即软删除业务关联、撤销下载权限并生成物理清理任务；原文件、分块和向量由幂等后台任务尽快清理，保留的衍生资产标记“来源已删除”；
- 删除知识库时沿用同一规则，且不得删除用户最后一个有效知识库。

文件上传与存储遵循以下统一规则：

- 后端按业务场景创建上传会话，前端不得自行声明所有者、对象存储 key、bucket、保留期或安全等级；
- 文件通过短期预签名地址直接上传受控对象存储；不超过 20 MB 使用单次上传，超过 20 MB 使用 16 MB 分片且浏览器最多并发上传 3 个分片；
- 上传会话默认 24 小时有效，有效期内允许续签上传地址和断点续传，过期会话及残留分片进入自动清理；
- 服务端不得信任扩展名、客户端 MIME、MD5 或客户端 SHA-256，必须流式计算 SHA-256 并校验真实类型、大小和文件结构；SHA-256 是正式内容身份，MD5 不作为唯一性或删除依据；
- 首期不接入病毒扫描引擎，不宣称具备病毒检测能力；仍需拒绝格式伪装、损坏或加密文件、带宏 Office 文件、PDF 嵌入附件、压缩炸弹、异常解压体积和含 NUL 字节的伪文本；
- 用户可同时选择最多 10 个文件，每个文件独立创建会话、展示状态和失败原因；每名用户最多同时存在 3 个上传中会话；
- 上传会话创建频率、未完成上传占用量、长期文件总量和短期录音总量均设置可配置的稳定性限制，不作为商业套餐额度；
- 上传状态、文件校验状态和业务解析状态分别建模。文件校验完成但尚未接入解析时显示“已上传·待解析”，不得冒充“可用”；
- 原始知识库资料在用户删除来源或删除账号前保留，以支持下载、移动和后续重新解析；校验失败的临时对象立即尝试删除，已完成但未绑定业务的对象 24 小时后清理；
- 文件名只用于展示，不作为唯一身份。对象 key 使用不可猜测标识且不包含用户名或原始文件名；同名不同内容可以共存，重命名不得修改真实扩展名、对象 key 或摘要。

首期默认文件策略如下，管理员只能在系统硬上限内调整：

| 场景 | 允许类型 | 默认限制 | 系统硬上限 |
| --- | --- | --- | --- |
| 知识库资料 | PDF、DOCX、TXT、MD | 50 MB；PDF 500 页；文本 200 万字符 | 100 MB；PDF 1000 页；文本 500 万字符 |
| 简历 | PDF、DOCX | 10 MB；文本 50 万字符 | 20 MB；文本 100 万字符 |
| JD | PDF、DOCX、TXT、MD | 10 MB；PDF 50 页或文本 50 万字符 | 20 MB；PDF 100 页或文本 100 万字符 |
| 真实面试录音 | MP3、M4A、WAV、WebM、OGG | 500 MB；180 分钟 | 1 GB；360 分钟 |
| 模拟面试录音 | 浏览器实际产生的 WebM/Opus、M4A/AAC | 500 MB；60 分钟 | 1 GB；90 分钟 |

DOCX 页数受字体、纸张和渲染器影响，首期不引入 Office/LibreOffice 渲染服务，也不以估算值冒充准确页数；DOCX 改为校验内部结构、解压后总量、正文字符数和段落数。图片 OCR、压缩包、可执行文件和视频继续不属于首期上传范围。

#### 7.1.2 解析与索引

- 提取正文、标题层级、页码或段落位置；
- 文本按可配置策略分块并写入向量库；
- 记录解析器、分块策略、向量模型和索引版本；
- 同一用户在同一知识库重复上传相同文件时返回稳定重复错误；同一用户在其他知识库已有相同文件时提示关联、移动或取消，并复用兼容的物理对象和后续解析结果；
- 不得跨用户共享文件权限、分块、向量或检索结果，即使文件哈希相同。

底层物理对象可以在存储安全等级和保留策略相同的范围内按服务端 SHA-256 去重，但跨用户只共享不可见的物理字节，不共享逻辑文件、权限、解析结果、分块、向量或检索结果。用户删除文件或账号时必须删除其全部逻辑所有权、引用和派生数据；若其他用户仍合法引用相同物理对象，该对象在最后一个有效引用消失后再物理删除。

#### 7.1.3 检索问答

- 用户可以限定一个或多个资料范围提问；
- 回答应附带可点击的来源文件和页码/段落引用；
- 检索不到充分证据时明确说明“资料中未找到”，不得编造来源；
- 用户可对回答进行有帮助/无帮助反馈；
- 对话可选择保存为笔记或生成练习题；
- 保存会话历史并自动生成标题，支持重命名和软删除；
- 资料模式下一个会话固定关联一个知识库，可在其中选择多个文件；
- 通用模式结果可以生成题目、笔记和难点，但所有衍生资产继承“模型通用知识”标记。

### 7.2 M2 出题与测评

#### 7.2.1 创建练习

用户可配置：

- 题目来源：资料、知识点、薄弱点、简历、JD 或组合；
- 题型：单选、多选、判断、简答，以及不执行代码的文本型编程题；
- 数量、难度、目标能力和是否限时；
- 练习模式或正式测评模式。

首期不提供在线代码运行环境。编程题答案仅作为文本或代码片段提交，可由 AI 根据评分规则点评，但系统不得声称已通过真实编译或测试。题目类型、答案结构和判分接口需预留代码执行结果字段，后续可接入隔离的代码沙箱。

练习模式逐题反馈、允许查看讲解和再次作答；正式测评在提交前不显示答案和评分，开始后锁定题目、评分规则和时间限制。正式测评自动保存答案，用户可在有效期内退出后继续；计时测评退出期间时间继续流逝，到时自动提交。

#### 7.2.2 题目质量

每道 AI 生成题必须包含：

- 题干、题型、难度和考查知识点；
- 标准答案或答案要点；
- 可执行的评分规则；
- 生成依据和资料引用；
- 题目生成状态与人工反馈入口。

系统应进行重复题、空答案、来源不足和格式异常校验。不合格题目不得进入正式测评。

题目只进入当前用户私有空间。开始答题前，用户可以删除、编辑或重新生成 AI 题目；开始正式测评后题目和评分规则不可修改。首期不设置管理员人工审核流程。

#### 7.2.3 答题与判分

- 支持暂存、继续作答、提交和超时自动提交；
- 客观题按确定规则判分；
- 主观题按评分维度给出等级、证据和置信度；只有评分规则明确且覆盖完整时才计算数值分数；
- 评分结果至少包含逐题结果、知识点掌握度、错误原因和改进建议；只有评分规则完整时才包含总分；
- 对低置信度的主观题评分明确标记，用户可申请重新评分。

重新评分不得覆盖原结果，应生成新版本并记录原因、模型版本、提示词版本和输入版本。旧评分保持可追踪，不用于跨领域排行榜或企业录用概率推断。

#### 7.2.4 薄弱点识别

- 错题或低分不直接等同于永久薄弱点；
- 系统综合题目难度、重复错误次数、近期表现和评分置信度生成候选薄弱点；
- 薄弱点包含来源场景、证据、严重程度、掌握状态和最后验证时间；
- 高置信度候选项自动进入难点资产库，其他候选项由用户确认；
- 用户可以确认、忽略、合并、撤销或标记“已掌握”。

### 7.3 M3 简历智能分析

- 支持上传 PDF/DOCX 简历，也支持粘贴文本；
- 抽取基本信息、技能、工作经历、项目经历、教育经历和成果数据；
- 用户可上传或粘贴目标 JD，并选择目标岗位；
- 输出结构完整性、表达清晰度、量化程度、岗位匹配度和潜在追问点；
- 优化建议必须说明原因，不得虚构经历、技能、指标或项目成果；
- 系统逐条展示原文、建议文本和修改原因，由用户接受或拒绝后生成新版本；
- 任何改写都不得覆盖原始简历；
- 支持比较不同版本，并将选定版本用于生成面试题。

### 7.4 M4 语音模拟面试

#### 7.4.1 面试配置

用户可选择：

- 使用的简历版本和目标 JD，二者均为可选；
- 未提供简历或 JD 时填写岗位、主题或能力要求，进入通用面试；
- 面试类型（技术面、项目面、综合面等）；
- 难度、问题数量、压力等级，以及 10、20、30、45 或 60 分钟时长档位，默认 20 分钟；
- 是否重点考察指定技能或历史薄弱点。

#### 7.4.2 面试过程

- 首期采用轮次式语音：AI 提问 → 用户语音回答 → 语音识别 → AI 追问；不提供文字模拟面试，也不要求连续双向打断；
- 开始前检测麦克风权限、录音与语音识别可用性；
- 每次开始录音前展示录音用途和保存期限，用户确认后才能开始；
- AI 面试官以语音提问，用户以语音回答；
- 页面实时展示转写，并允许用户标记转写错误；
- AI 根据用户回答进行上下文追问，不机械朗读固定题库；
- 系统控制题目数量、单题时间、追问次数和整体时长；
- 用户可手动结束回答；连续静音达到配置时长时显示短暂倒计时并自动结束回答；
- 只能在两个问题之间暂停，默认最多 5 分钟；超时后自动结束并基于已有完整轮次生成报告；
- 异常断线后默认 10 分钟内允许恢复，时间可配置；恢复时从最近一个完整问答轮次继续，未完成回答不参与评分；
- 系统保存模拟面试原始录音，默认保留 7 天；保留天数由系统参数配置；
- 面试创建时固化录音过期时间，管理员修改配置只影响新面试；
- 录音详情展示明确到期时间和剩余天数；到期后展示“录音已清理”状态；
- 录音未过期时，用户可以通过短期授权地址下载自己的录音；管理员不得下载；
- 全程明确提示录音、转写和 AI 处理状态。

#### 7.4.3 面试结果

面试结束后异步生成：

- 逐题问题、回答转写、追问链和参考要点；
- 技术正确性、逻辑结构、表达清晰度、岗位匹配度等维度评分；
- 每项评分对应的回答证据；
- 做得好的部分、需要改进的部分和可执行训练建议；
- 优秀回答示例；
- 本轮新增或再次验证的薄弱点。

评分采用基础维度加面试类型专属维度。基础维度至少包括内容相关性、逻辑结构和表达清晰度；技术面、项目面和综合面使用各自扩展维度并向用户展示规则。只有规则完整时展示总分，否则展示分项等级与总结，始终标记“AI 评估”。

面试过程中不允许编辑转写。结束后用户可修正转写并申请重新评分；系统保留原始转写和原报告，修正版生成新的报告版本。

### 7.5 M5 难点攻克资产库

#### 7.5.1 难点来源

难点可来自：资料问答、学习测评、模拟面试、真实面试复盘或用户手动创建。

#### 7.5.2 难点资产

每个难点至少包含：

- 名称、所属领域和标签；
- 来源任务与证据；
- 当前掌握状态和优先级；
- 结构化知识卡片；
- 通俗解释、原理、示例、常见误区和练习；
- 可选的讲解音频及对应文本；
- 复习记录和再次测评结果。

#### 7.5.3 状态流转

正式难点进入资产库后异步生成知识卡片；低置信度候选项未确认前不生成。重复难点优先更新已有资产，不重复创建。状态统一为：待学习 → 学习中 → 待验证 → 已掌握；再次答错后可回到学习中。状态变化应保留历史记录。

讲解音频由用户点击后按需生成，生成结果保存并复用，重复播放不得再次调用语音合成。

### 7.6 M6 笔记本

- 资料问答、测评、模拟面试、真实面试复盘和难点资产页面提供“生成笔记”入口，由用户主动触发；
- 系统不得在回答、测评或面试结束后自动创建笔记，也不得仅因为内容被判定为“有价值”就写入笔记本；
- 用户点击“生成笔记”后，笔记生成 Agent 根据当前选定内容生成预览；用户确认保存后才创建正式笔记；
- 用户取消预览时不创建笔记；同一来源重复触发时提示继续编辑已有笔记或创建新笔记；
- 用户可新建、编辑、删除、归档、搜索和按标签筛选；
- AI 生成内容与用户编辑内容需要可区分，重新生成不得覆盖用户修改；
- 笔记保留关联资料、题目、报告和难点的双向链接；
- 支持 Markdown 风格正文、代码块、列表和引用；
- 首期至少支持导出 Markdown。

里程碑一、二只提供页面查看；里程碑三统一交付面试报告 PDF 导出，以及笔记、知识卡片 Markdown 导出。

### 7.7 M7 真实面试复盘

- 用户可上传常见音频格式，并查看大小和时长限制；
- 首期仅支持中文普通话录音，不承诺识别方言、外语或多语混合内容；
- 上传前展示录音用途、第三方处理和保存期限，并要求用户确认其有权处理该录音；
- 系统完成说话人区分、时间戳转写和文本校正；
- 系统先以“说话人 1/2/3”展示结果，用户可以合并说话人、修正文本并指定自己和面试官；
- 用户确认说话人和转写后才生成正式报告；角色无法可靠确认时不得生成确定性评分；
- 自动识别面试问题、用户回答、追问链和关键讨论主题；
- 输出逐题点评、整体表现、薄弱点、改进建议和复习清单；
- 用户可编辑转写后重新生成复盘，原报告保留版本；
- 转写或角色区分置信度过低时应提示用户人工校正，不直接生成确定性结论。

真实面试原始录音与模拟面试使用同一保留策略：默认 7 天且可配置，创建时固化过期时间；未过期时用户可以下载，过期后只保留转写、报告和“录音已清理”状态。

### 7.8 M8 提示词管理器

该模块仅对管理员开放。

- 按智能体和任务类型维护提示词模板；
- 支持变量定义、必填校验、版本管理、草稿、发布和回滚；
- 发布前使用固定样例做预览或回归测试；
- 运行任务记录所使用的提示词版本；
- 提示词不得直接拼接未经隔离的用户文档指令，需防范提示词注入；
- 敏感密钥和系统提示词不得返回前端。

首期不设置管理员人工审核 AI 题目的流程。题目只进入当前用户的私有空间，不提供公开发布；用户需对其上传资料的来源和使用行为负责。系统仍需执行格式、空内容、重复题和基础内容安全校验，这些自动校验不属于人工审核。

用户资料和指令还需经过模型安全能力与基础规则校验，拦截明显违法、有害或危险任务。安全校验不得成为管理员查看用户原文的入口。

### 7.9 M9 个性化学习计划

- 用户可以创建多个学习计划，每个计划关联一个知识库或求职目标，并可设置一个当前重点计划；
- 用户设置学习目标、目标日期、每周可用时间和偏好；任务创建页就地收集必要画像，并允许保存为默认偏好，不设置强制首次引导；
- 系统依据能力画像、薄弱点、待复习资产和最近完成情况生成计划；
- 计划由可完成的任务组成，如阅读资料、完成测评、复习难点、再次面试；
- 用户可调整、跳过或完成任务，系统记录原因；
- 新测评或新复盘完成后，系统可提出调整建议，但未经用户确认不大幅改写整个计划；
- 学习计划作为独立一级页面，展示任务、进度、即将到期项目和近期能力变化；测评、面试和难点页面提供“加入计划”入口；未来工作台只负责聚合，不改变计划数据模型。

## 8. 核心业务流程

### 8.1 学习模块流程

#### 8.1.1 学习快速回答

1. 用户进入学习模块，默认选中“快速回答”。
2. 用户选择资料模式或通用模式；资料模式还需选择知识库和可选文件范围。
3. 用户输入问题并发送。
4. 总控调度检索与回答能力；资料模式执行 RAG 检索，通用模式使用千问通用知识。
5. 系统生成回答；资料模式展示可定位引用，通用模式展示“模型通用知识”标记。
6. 用户可以继续追问、反馈结果，或主动点击“生成笔记”。
7. 用户触发生成笔记时，系统生成笔记预览；用户确认后才保存到笔记本。

成功终点：用户获得来源边界明确的直接回答，系统不会自动创建笔记。

#### 8.1.2 学习知识精讲

1. 用户选择“知识精讲”。
2. 用户输入知识点、选择已有薄弱点，或从其他结果页跳转进入。
3. 用户选择资料模式或通用模式，并补充当前基础、期望深度等可选信息。
4. 难点讲解 Agent 生成结构化知识卡片，至少包含概念、原理、示例、常见误区和练习。
5. 用户可按需点击“生成讲解音频”，系统生成并保存可复用音频。
6. 用户可主动点击“生成笔记”，预览并确认后保存。

成功终点：用户获得适配自身水平的结构化讲解，并可继续练习、生成音频或沉淀笔记。

#### 8.1.3 学习刷题评测

1. 用户选择“刷题评测”。
2. 用户输入岗位、技术栈或题目需求，也可选择资料、简历或已有薄弱点。
3. 出题 Agent 二次向用户确认题型、难度、题量、目标能力和是否限时。
4. 用户确认后，出题 Agent 生成题目、答案要点、评分规则和来源信息。
5. 用户在开始前删除、编辑或重新生成题目；开始正式测评后题目锁定。
6. 用户完成答题并提交。
7. 点评诊断 Agent 完成逐题评价、证据说明和改进建议，并识别候选薄弱点。
8. 高置信度薄弱点自动进入难点资产库，其他候选项由用户确认。
9. 用户可从薄弱点进入“知识精讲”，也可主动生成笔记或加入学习计划。

成功终点：用户获得可信、可解释的测评结果，薄弱点能进入后续精讲与训练闭环。

### 8.2 面试模块流程

#### 8.2.1 面试快速回答

1. 用户进入面试模块，默认选中“快速回答”。
2. 用户选择资料模式或通用模式，并输入面试问题。
3. 系统生成针对该问题的回答思路、结构和参考答案，并标记知识来源。
4. 用户可继续追问、反馈结果，或主动生成笔记。

成功终点：用户快速获得一份来源边界明确的面试问题参考答案。

#### 8.2.2 简历优化

1. 用户选择“简历优化”。
2. 用户上传或粘贴简历，可选上传或粘贴 JD。
3. 资料解析与简历分析 Agent 提取简历结构并进行深度分析。
4. 系统逐项展示优势、问题、潜在追问点，以及原文、建议文本和修改原因。
5. 用户逐条接受或拒绝修改建议。
6. 系统基于已接受建议生成新的简历版本，原始简历保持不变。
7. 用户可使用新版本直接进入“模拟面试”，或主动生成简历分析笔记。

成功终点：用户获得经过确认的新简历版本，系统没有虚构或未经确认覆盖用户经历。

#### 8.2.3 模拟面试

1. 用户选择“模拟面试”。
2. 用户选择可选的简历、JD，或填写岗位、主题和能力要求。
3. 总控形成候选人/岗位画像，出题 Agent 生成面试题和追问方向。
4. 用户配置面试类型、难度、时长、题量、压力等级和重点能力。
5. 用户确认录音规则并通过设备检测后开始面试。
6. 模拟面试官 Agent 以轮次式语音完成提问、回答识别和动态追问。
7. 面试结束后固化录音、原始转写和事件记录。
8. 点评诊断 Agent 生成逐题与整体报告，识别薄弱点并给出改进建议。
9. 用户可修正转写并生成新的报告版本。
10. 用户可从薄弱点进入“知识精讲”，也可主动生成复盘笔记或加入学习计划。

成功终点：用户获得一份有回答证据、改进动作和后续训练入口的模拟面试报告。

#### 8.2.4 面试复盘

1. 用户选择“面试复盘”。
2. 用户确认录音处理规则并上传中文普通话真实面试录音。
3. 系统校验录音，完成带时间戳的转写和说话人区分。
4. 用户校正转写、合并说话人，并指定本人和面试官角色。
5. 用户确认后，总控调度点评诊断与复盘 Agent。
6. Agent 提取问题、回答、难点和表现证据，生成逐题及整体复盘报告。
7. 系统沉淀候选薄弱点；用户可进入“知识精讲”、主动生成笔记或加入学习计划。

成功终点：报告结论能定位到具体时间片和转写内容，用户可以修正识别错误后重新分析。

#### 8.2.5 面试知识精讲

1. 用户选择“知识精讲”，或从模拟/真实面试报告中的薄弱点进入。
2. 用户选择待讲解薄弱点或输入指定知识点，并可补充资料范围。
3. 难点讲解 Agent 生成结构化知识卡片和针对面试场景的表达建议。
4. 用户可按需生成讲解音频、针对该难点继续刷题，或再次发起模拟面试。
5. 用户可主动生成笔记，确认预览后保存。

成功终点：面试短板被转化为可学习、可练习、可再次验证的个人资产。

### 8.3 难点沉淀通用流程

1. 任意学习或面试模式产生候选薄弱点。
2. 总控收集来源、证据、知识点和用户画像。
3. 系统合并重复难点，或更新既有难点的证据与严重程度。
4. 正式难点进入个人难点资产库，并由难点讲解 Agent 生成标准化知识卡片。
5. 系统不得自动创建笔记；用户需要时主动触发笔记生成并确认保存。
6. 后续出题、模拟面试和学习计划优先使用未掌握难点。

- 持久化实体复用统一主键能力；需要更新时间的实体复用 `created_at`、`updated_at` 时间戳能力；
- 需要追踪操作者的实体复用 `created_by`、`updated_by` 审计人能力，系统自动创建时允许为空；
- 支持软删除的实体复用 `deleted_at`、`deleted_by` 能力；正常业务查询、RAG 检索和 Agent 上下文必须默认排除已删除数据；
- 不得为了继承方便强迫所有表拥有无意义字段。追加式事件、关联表或纯技术表只组合真实需要的公共能力，例如认证审计事件只有创建/发生时间，不提供修改时间和修改人。

用户主动删除的数据采用软删除；首期不提供恢复入口。原始文件、分块、向量和录音按删除或保留策略物理清理，数据库业务记录保留软删除状态。模拟与真实面试原始录音记录独立过期时间，默认 7 天到期后清理对象存储文件；转写、报告和难点继续保留，直到用户主动删除。

物理对象、用户逻辑文件和业务关联必须分层建模。业务关联是用户操作的资源；物理对象只有在最后一个有效逻辑引用消失并再次复核后才允许删除。引用计数可以作为性能字段，但有效引用记录才是删除判断的事实源；计数不一致时停止删除并进入一致性修复。

## 11. 任务状态与异常处理

### 11.1 通用异步任务状态

统一使用：待处理 → 处理中 → 已完成 / 已失败 / 已取消。

- 长任务刷新页面后仍可查看进度；
- 前端不得仅依靠本地状态判断任务完成；
- 后端通过任务 ID 提供状态查询，必要时使用 SSE/WebSocket 推送业务阶段；
- 全局任务中心展示任务类型、业务对象、负责角色、阶段、状态、失败原因、取消和重试入口，不展示内部提示词或推理；
- 任务完成或失败后产生站内通知，用户重新登录后仍可查看未读结果；首期不发送短信或邮件；
- 每类任务设置管理员可配置的并发上限，超过上限进入队列；同一用户同一时间最多进行一场语音面试；
- 排队任务可以立即取消；运行中任务进入“取消请求”状态，在安全节点停止并丢弃未发布结果；已完成任务不能改为已取消；
- 重试必须具备幂等性，避免重复题目、报告、笔记或扣费；
- 失败结果保留失败节点和用户可理解的错误信息。

### 11.2 关键异常场景

- 文件损坏、加密、格式不支持或内容为空；
- 文档无法提取有效文本、音频无有效声音、转写置信度过低；
- 模型超时、限流、内容安全拒绝或返回结构不合法；
- RAG 未检索到充分证据；
- 模拟面试中断、麦克风拒绝授权或网络断开；
- 同一任务被重复提交；
- 用户删除仍被任务引用的资料。

每类异常需明确：是否可重试、是否需要用户修正、是否保留已有进度。首期不展示费用或额度信息。

### 11.3 用户反馈

- 题目、回答、评分、转写和讲解均提供反馈入口；
- “无帮助”或“评分有误”需记录原因，并提供重新生成或重新评分入口；
- 反馈不得直接修改或发布全局提示词；
- 管理员只查看脱敏统计，不能通过反馈记录读取对应用户正文。

### 11.4 文件清理与一致性

- 删除接口立即撤销业务可见性与下载授权，并创建持久化清理任务；文件物理删除不依赖 HTTP 请求生命周期；
- 独立 worker 从 PostgreSQL 持久化任务中领取工作，任务领取、状态转换、引用变更和最终结果必须幂等；FastAPI 进程内临时后台任务不得成为唯一执行机制；
- 独立 scheduler 使用数据库锁保证多实例下只有一个有效调度者，每天 `02:30 Asia/Shanghai` 扫描到期录音、过期上传、临时对象和失败清理任务；
- 用户主动删除和账号清理任务优先于普通临时文件清理；确定性校验失败不重试，短暂存储或数据库故障最多重试 3 次，物理删除最多重试 8 次，超过上限后进入最终失败并告警；
- 每周日 `03:30 Asia/Shanghai` 对账 PostgreSQL、RustFS 与引用状态。首次发现的孤儿对象只登记候选，连续两次确认且至少存在 7 天后才允许删除；
- 数据库存在记录但对象缺失时将文件标记为不可用并告警，不伪造成功；引用计数不一致时先修复，停止当前物理删除；
- 用户删除账号时，账号删除业务编排必须调用可执行、可测试的用户文件清理能力，立即撤销全部文件访问；完整账号删除接口另行通过独立 OpenSpec 实现；
- 上传会话成功或过期元数据、成功清理任务保留 90 天，最终失败任务和脱敏文件访问审计保留 180 天，文件策略历史版本长期保留。

## 12. AI 结果质量要求

1. **有依据**：基于用户资料的结论提供来源；基于回答的评分提供原文证据。
2. **不造假**：简历优化不得创造用户未提供的事实，资料问答不得虚构引用。
3. **结构稳定**：Agent 输出需通过 Schema 校验，失败后按规则修复或重试。
4. **可解释**：评分同时给出维度、规则、证据和建议，不能只给总分。
5. **可反馈**：用户可反馈题目、答案、评分、转写或讲解存在问题。
6. **可复现**：保存模型、参数、提示词版本和输入引用，便于质量回溯。
7. **有评测集**：上线前至少建立资料问答、出题、简历分析、主观评分和面试复盘的代表性样例。
8. **历史稳定**：模型或提示词升级不得自动重算旧内容；用户主动重新生成或重评时创建新版本。
9. **来源明确**：资料模式提供可定位引用，通用模式及其衍生资产明确标记“模型通用知识”。

首期上线质量门禁为：结构化输出成功率不低于 99%，资料引用可定位率不低于 95%，无充分资料依据时的正确拒答率不低于 90%。评测集结果必须经过人工抽样复核，未达到门禁不得发布对应提示词或模型版本。

## 13. 非功能需求

### 13.1 性能与体验

- 首期容量基线：1,000 个注册用户、50 个同时在线用户、5 场并发语音面试；
- 在容量基线内，非 AI 列表和详情接口 P95 不超过 1 秒，提交类接口 P95 不超过 2 秒；
- 文档解析、题目生成、报告生成和音频转写采用异步任务；
- 资料问答目标 15 秒内开始返回，普通题目生成目标 60 秒内完成，面试报告目标 3 分钟内完成；
- 轮次式语音面试在用户结束回答后，目标 3 秒内开始播放下一次提问或追问；
- 所有长任务展示阶段、进度或明确的处理中状态，禁止无限加载无反馈。

以上为首期目标值，应在测试环境压测并监控 P95。超过目标时间不等同于立即失败，系统继续展示进度；达到任务超时上限后明确失败并允许重试。

### 13.2 安全与隐私

- 简历、录音、转写和学习资料均按敏感用户数据处理；
- 传输使用 HTTPS，敏感存储需加密或采用受控对象存储；
- 文件下载使用短期授权地址，禁止公开永久链接；
- 服务端校验文件真实类型、大小、结构与受控解析边界；首期不接入病毒扫描，不得把格式校验宣传为病毒检测；
- 用户文档视为不可信输入，防范提示词注入和跨用户检索；
- 未经用户单独同意，不得将用户内容用于模型训练；
- 用户首次使用 AI 功能时，明确提示相关内容会发送给千问服务处理并记录确认；不在每次调用时重复弹窗；
- 用户可删除原始文件、录音、转写和衍生资产，并看到删除影响；业务数据删除采用软删除；
- 模拟面试原始录音默认保留 7 天，到期自动清理实际录音文件，保留周期支持系统配置；
- 文件下载每次重新校验当前用户与业务引用权限，只返回短期授权地址；普通资料默认 5 分钟有效，录音默认 15 分钟有效，管理员不得下载用户业务文件；
- 生产环境上传与下载使用 HTTPS，对象存储使用实际支持且经过验证的静态加密能力或受控私有存储；密钥不得进入数据库、Git、日志或 API；
- 记录登录、权限变更、敏感数据访问和管理员操作审计日志。

### 13.3 可靠性与可观测性

- 每次用户任务拥有全链路 request/task ID；
- 记录各 Agent 节点耗时、成功率、重试次数、模型用量和错误类型；
- 千问调用失败时只在千问体系内按规则重试，仍失败则明确任务失败；首期不静默切换其他厂商模型，也不返回伪成功结果；
- 对关键任务设置超时、重试上限和失败告警；
- 数据库、对象存储和向量库之间需要可核对的一致性策略；
- 生产环境每日备份，首期目标 RPO 24 小时、RTO 4 小时，正式上线前至少完成一次恢复演练；
- 日志默认只记录 ID、状态、耗时、版本和错误码，禁止记录用户资料、简历、答案、对话、转写或系统提示词正文；
- 首期只采集自有运行指标和脱敏产品事件，不接入第三方用户行为分析平台。

### 13.4 兼容性与可访问性

- 首期支持 Chrome、Edge 最近两个主要版本和最新版桌面 Safari；
- 语音面试优先保证桌面 Chrome/Edge；能力不足的浏览器明确提示，不自动切换为文字面试；
- 登录、内容阅读、答题、报告、难点和笔记适配移动端；复杂资料上传、简历编辑和语音面试首期以桌面端为主；
- 键盘可完成主要操作，表单有明确标签与错误提示；
- 图表与评分不只依靠颜色表达状态；
- 录音和音频讲解提供文本替代内容。

### 13.5 模型与额度

- 首期大语言模型、语音识别和语音合成统一使用千问/阿里云体系，具体模型与服务 ID、接口地址和鉴权信息通过服务端配置；
- 业务代码不得写死具体千问模型版本，模型调用层需保留替换实现；
- 首期不设计用户级模型调用额度、套餐、计费或额度耗尽交互；
- 系统仍应记录模型调用次数、耗时和错误，用于稳定性排障，不作为用户额度控制。

### 13.6 部署与防滥用

- 产品按可部署的多用户 Web 系统设计，首期允许单实例部署；
- 开发、测试、生产使用独立配置，文件路径、服务地址和密钥不得写死；
- 开放注册首期不提供验证码；注册/登录接口必须具备账号与 IP 双维度限流、异常调用频率限制和账号封禁能力；
- 技术并发限制和文件限制用于保护系统稳定性，不作为商业套餐或用户额度；
- 文件策略采用不可变发布版本；上传会话创建时固化策略版本和限制快照，普通配置变更只影响新会话，安全紧急禁用可以终止尚未完成的相关会话；
- 每名用户默认每小时最多创建 30 个上传会话、未完成上传最多占用 2 GB、长期文件最多 10 GB、短期录音最多 10 GB；系统硬上限分别为长期文件 50 GB 和短期录音 50 GB；
- 数据库与对象存储备份默认加密保留 30 天，已删除文件在在线存储及时清理并随备份周期自然淘汰；从旧备份恢复后必须先重放删除墓碑，防止已删除内容重新出现。

## 14. 首期交付里程碑

首期由三个可独立运行、独立验收的里程碑组成。不得等全部模块完成后才进行首次集成。

### 14.1 里程碑一：学习闭环

- 注册、登录、会话恢复与退出、账号删除和管理员用户管理；
- 知识库、PDF/DOCX/TXT/Markdown 上传、解析和检索；
- 学习模块模式选择：快速回答、知识精讲、刷题评测；
- 资料模式、通用模式和历史问答会话；
- 出题、练习模式、正式测评、评分版本；
- 候选薄弱点、难点资产和文字知识卡片；
- 任务中心、站内通知、软删除、并发控制和基础管理配置。

成功闭环：资料 → 问答/出题 → 答题 → 点评 → 难点卡片。

### 14.2 里程碑二：模拟面试闭环

- 面试模块模式选择：快速回答、简历优化、模拟面试；
- 简历与 JD 解析、逐条优化和版本管理；
- 通用或个性化的轮次式语音模拟面试；
- 静音结束、暂停、断线恢复、录音保存与下载；
- 转写修正、分类型评分、报告版本和难点沉淀；
- 千问/阿里云语音能力、录音 7 天保留策略。

成功闭环：简历/JD/主题 → 模拟面试 → 转写 → 点评 → 难点卡片。

### 14.3 里程碑三：资产与真实复盘

- 补齐面试复盘模式，并打通面试知识精讲入口；
- 笔记本、按需生成笔记和讲解音频；
- 真实面试录音上传、多人转写校正和角色确认；
- 真实面试复盘、报告和学习计划联动；
- 多学习计划、重点计划和任务调整；
- 提示词管理器、评测门禁和版本回滚；
- 面试报告 PDF、笔记与知识卡片 Markdown 导出。

### 14.4 后续范围

- 更多文档、图片和视频理解能力；
- 在线编程题代码沙箱与真实运行结果判分；
- 首次引导和可配置工作台；
- 更丰富的面试类型和岗位模板；
- 间隔复习、学习效果实验与个性化策略优化；
- 在取得用户授权和隐私评估后探索分享或协作能力。

## 15. 首期验收标准

### 15.1 学习闭环

- 用户可以使用符合规则的唯一用户名、昵称和密码注册，注册成功后自动登录并进入当前默认受保护入口；内容库上线后默认进入内容库；
- 用户刷新页面后可以通过 Refresh Token 恢复会话，退出后当前 Access Token 和 Refresh Token 均不可继续访问受保护接口；
- 登录失败达到账号或 IP 限制时返回明确的限流状态，但不得泄露账号是否存在；
- 注册、登录、刷新、退出和 Refresh Token 重放场景在后端接口完成后必须先通过可重复执行的 `curl` 验证，再进入前后端联调；
- 登录、注册、刷新恢复和退出的真实浏览器流程必须通过 Playwright E2E；测试使用独立 PostgreSQL 数据库和独立 Redis key 空间，不得清空日常开发数据；
- 学习模块清晰展示快速回答、知识精讲、刷题评测三种模式，默认选择快速回答；
- 切换模式后，输入表单、提交动作和结果组件与对应流程一致，不保留无关表单值；
- 注册后自动创建默认知识库；用户能创建、移动和删除资料，并在删除前看到影响范围；
- 后端支持知识库列表、创建、重命名和删除，且不得删除用户最后一个有效知识库；本阶段先交付后端接口，不实现内容库前端页面；
- 有效文件通过业务范围内的上传会话获得短期预签名地址，上传完成后由服务端复核 SHA-256、真实类型、大小和结构，客户端声明不得成为安全依据；
- 同一知识库重复文件被明确拒绝，同一用户其他知识库中的相同文件可选择关联或移动；跨用户不得通过重复响应推断他人是否上传过相同内容；
- 文件重命名只修改当前知识库中的展示名称；下载、删除、移动和重复操作均重新校验所有权，管理员不能下载用户文件；
- 删除前影响预览返回短期一次性确认凭证；资源发生变化时旧凭证失效，删除立即撤销访问并由幂等后台任务完成物理清理；
- 用户上传一份有效 PDF/DOCX/TXT/Markdown 后能看到解析状态，成功后可发起带来源引用的资料问答；
- 资料模式固定知识库范围且引用可定位；通用模式及衍生资产明确标记“模型通用知识”；
- 用户能基于指定资料生成一组题目并完成提交；
- 练习模式支持逐题反馈，正式测评锁定题目并支持断点继续；
- 每道主观题评分包含评分维度、回答证据、置信度和改进建议；重评产生新版本；
- 错误或低分知识点可生成难点资产，且能从原测评跳转查看；
- 各学习模式只在用户点击“生成笔记”并确认预览后创建笔记，流程结束不会自动写入；
- 资料无法解析或模型失败时展示明确原因，可按规则重试。

### 15.2 面试闭环

- 面试模块清晰展示快速回答、简历优化、模拟面试、面试复盘、知识精讲五种模式，默认选择快速回答；
- 每种面试模式能够独立走完第 8.2 节定义的开始、处理和成功终点；
- 用户可以基于简历/JD 或仅基于岗位、主题发起面试；
- 上传简历并粘贴 JD 后可看到结构化画像、逐条优化建议和潜在追问点；
- 用户通过设备检测后可完成一场多轮语音模拟面试；
- 面试中至少发生基于用户回答的有效追问，而非只播放固定问题；
- 面试结束后可查看带时间顺序的转写、逐题点评和整体报告；
- 报告中的关键结论能定位到具体回答证据，并生成关联薄弱点；
- 用户能修正面试后转写并生成新报告版本，原始转写和报告仍可追踪；
- 模拟面试原始录音默认保留 7 天，修改系统参数后新录音按新周期计算过期时间；
- 用户能看到录音到期时间并在到期前下载；到期后显示“录音已清理”；
- 非中文普通话的真实面试录音被明确提示为不支持，不进入正式复盘流程；
- 真实面试必须经过说话人和用户角色确认后才能生成正式报告。
- 各面试模式只在用户点击“生成笔记”并确认预览后创建笔记，流程结束不会自动写入。

### 15.3 数据与安全

- 两个不同用户无法访问彼此的文件、题目、录音、报告和笔记；
- 删除原始敏感数据时，用户能确认删除范围和衍生影响，删除后数据不再出现在正常查询、检索或 Agent 上下文中；
- 系统管理员能查看用户列表、基本信息并启用或禁用普通用户，但无法重置密码，也无法通过管理页面或接口读取用户业务数据；
- 管理员可启用、禁用普通用户，但不能管理其他管理员；
- 管理员提示词变更有版本、发布人和回滚能力；
- 任意失败任务可通过 task ID 在日志中定位到失败节点，日志不包含用户正文；
- 排队任务能取消，运行中任务能在安全节点停止；任务完成和失败产生站内通知。

### 15.4 性能与质量

- 在首期容量基线内完成普通接口和语音并发压测，并达到第 13.1 节的 P95 目标；
- 通过固定 AI 评测集，达到结构化输出、引用定位和正确拒答门禁；
- 千问不可用时任务明确失败，不静默切换其他厂商或返回伪成功结果；
- 完成一次生产备份恢复演练，验证 RPO/RTO 目标；
- Chrome、Edge、Safari 和移动端阅读范围按第 13.4 节完成兼容性验收。

## 17. 产品决策审查结论

本需求基线已完成多轮产品决策审查，以下口径不再作为待确认问题：

1. 首期按三个独立里程碑交付，不要求九个模块一次性完成。
2. 产品入口覆盖所有学习领域和岗位，专业内容以用户材料为主。
3. 资料模式和通用模式严格区分，来源标记随衍生资产继承。
4. 用户以知识库组织资料，会话固定模式和知识范围。
5. 多 Agent 是独立业务组件，由状态机统一调度，首期同应用部署。
6. 普通用户开放注册；管理员由部署初始化，只管理普通用户账号。
7. 模拟面试采用轮次式语音；真实面试先校正说话人与转写再分析。
8. 模拟和真实原始录音默认保存 7 天，转写和报告长期保留至用户删除。
9. 用户数据软删除，原始文件、分块、向量和录音按策略物理清理，首期不提供恢复入口。
10. 首期使用千问/阿里云模型与语音体系，不设置用户额度或计费。
11. AI 题目不做人工审核，只在用户私有空间使用；保留自动质量与内容安全校验。
12. 笔记和讲解音频按需生成；学习计划独立管理，并允许多个计划。
13. 历史报告和资产不因模型升级自动变化，重评或重新生成创建新版本。
14. 任务中心、站内通知、并发排队、取消、重试和脱敏日志属于首期基础能力。
15. 性能容量、AI 质量、浏览器兼容、备份恢复和防滥用均有明确验收门禁。
16. 学习模块和面试模块以用户主动选择的业务模式路由不同流程；业务模式与资料/通用知识模式分别建模。
17. 笔记只能由用户主动触发生成并确认保存，任何模式不得自动写入笔记本。
18. 首期认证只包含注册、登录、刷新、当前用户和退出，不提供首次强制改密、找回密码或管理员重置密码。
19. 登录态采用 15 分钟 Access Token 与绝对 7 天 Refresh Token；Refresh Token 通过 `HttpOnly` Cookie 轮换并支持服务端撤销与重放检测。
20. 普通用户注册后自动启用并自动登录；开放注册首期不使用验证码，通过账号/IP 双维度限流防滥用。
21. 数据库模型按能力组合公共主键、时间、操作人和软删除 Mixin，不在每张表重复声明，也不为不适用的表强加公共字段。
22. 文件上传采用业务范围内的两阶段上传会话与短期预签名地址，服务端 SHA-256 是正式内容身份；MD5 和客户端摘要不作为可信唯一性依据。
23. 物理对象、用户文件资产和知识库关联分层；同一用户可跨知识库关联或移动相同文件，跨用户只允许兼容存储域中的不可见物理字节去重。
24. 首期文件安全边界包含真实类型、结构、大小和解析资源限制，但暂不接入病毒扫描引擎，也不宣称具备病毒检测能力。
25. 文件删除立即撤销业务访问并进入持久化清理队列；独立 worker、scheduler 和周期对账共同保证数据库、对象存储及未来向量数据的一致性。
26. 当前文件变更先交付后端知识库与公共存储接口，不开发内容库前端，不实现文档解析、分块、Embedding 或检索；上传完成后准确显示为“已上传·待解析”。
27. 文件策略版本化并由管理员通过后端接口管理，上传会话固化策略快照；默认值、硬上限、上传并发和存储保护规则已经确认，不再作为未决参数。

具体千问模型 ID、接口地址、静音秒数和通用 AI 任务超时属于技术设计阶段的可配置参数，不改变本文业务规则，无需再次进行产品范围决策。文件类型、默认大小、硬上限、上传并发、会话时长、录音保留和清理调度已经在本文确认；认证 Token 时长已经在第 4.4 节确认，不再作为未决参数。
